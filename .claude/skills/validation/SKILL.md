# Этап 5. План проверки и решение

Текущее состояние: !`python3 "${CLAUDE_PROJECT_DIR}/scripts/project.py" status --short`

Методика: `methodology/experiments.md`, `methodology/decision-records.md`.

## Шаги
1. Собери, что проверять: гипотезы из «что должно быть правдой» выбранного варианта, свойства-гипотезы из `product-properties.json`, все «тесты сообщения» из `out/comms-strategy.md` (их ID MSG-xx обязаны попасть в план). Самые рискованные и дешёвые в проверке — первыми.
2. Для каждой проверки (`out/validation-plan.md`, шаблон [template.md](template.md)):
   - **ожидаемое изменение** — метрика, направление и величина (это прогноз: `claims.py add` с `kind: forecast`, `basis`);
   - **с чем сравниваем** — контрольная группа; если её нет — до/после или сопоставимый сегмент с оговорками;
   - **срок наблюдения** и почему такой (цикл решения клиента, сезонность, грубая оценка выборки);
   - **нежелательные последствия** — guardrail-метрики и порог, при котором останавливаем;
   - **критерий успеха** и **kill-критерий** (при каком результате решение отменяется или меняется);
   - ответственный (роль) и стоимость проверки (порядок величины).
3. Запиши/обнови решение в `state/decisions.md`: статус, основания (ID утверждений), **итоговый вердикт** «делать / нужна ясность / стоп» с причиной, **«Что заставит пересмотреть»** — конкретные kill-критерии из плана (заглушки на этом этапе не проходят), дата пересмотра. Проверка: `python3 scripts/decision_lint.py --fix`; пересмотр по новым данным — `scripts/revisit.py`.
4. Итог для получателя — `out/summary.md` (одна страница): вопрос → **вердикт** и рекомендация → почему (3 опоры с метками) → что не знаем → что проверяем и когда решаем снова → стоимость работы агента (`python3 scripts/cost_report.py`).
5. Ворота: `python3 scripts/promise_lint.py` (тесты сообщений теперь в плане), `python3 scripts/verify_claims.py --fix`, `python3 scripts/decision_lint.py --fix`.
6. **Точка человека:** покажи план проверки и решение, спроси утверждение kill-критериев (`project.py wait "Утвердить план проверки и kill-критерии"`). После ответа: `python3 scripts/project.py stage done --note "..."`.

## Готово, когда
У каждой ключевой гипотезы и каждого теста сообщения есть ожидаемое изменение, сравнение, срок, guardrails и kill-критерий; решение записано с основаниями; `out/summary.md` готов.
