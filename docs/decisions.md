## 2026-11-17 · Решение: состав агента
Сжатое ядро из 5 скиллов + «ворота качества» на Python: сверка обещаний, облегчённый протокол доказательств, сравнение с обычным чатом. Should: синтетические интервью, облегчённая «живая стратегия».
Почему: И1 и И2 дословно закрывают критерий 1, проверки детерминированные и работают без Claude (риск блокировки в РФ), не зависят от брифа демопроекта (critique.md §5).
Что отвергли: граф depends_on, eval на 6+ задачах с судьёй, три режима глубины, Jev как обязательную зависимость, «очную ставку» с реальными отзывами.

## 2026-11-17 · Решение: структура репозитория «агент отдельно от разработки»
AGENTS.md — единый источник инструкций агента (Claude Code читает его через `@AGENTS.md` в CLAUDE.md, Cursor — напрямую и через `.cursor/rules/strategist.mdc`). Хакатонный контекст перенесён в docs/dev/CONTEXT.md. docs/ и pitch/ — материалы разработки, агенту не нужны.
Почему: жюри откроет репозиторий в Claude Code, и корневой CLAUDE.md должен быть инструкцией стратега, а не нашего процесса.

## 2026-11-17 · Решение: снимок источника делает скрипт, читает — карантинный субагент
`scripts/fetch_source.py` сохраняет страницу в materials/ и печатает только путь; оркестратор не видит текст источника. Читает `source-reader` (Haiku, без Write/Bash/Edit) и возвращает только JSON утверждений. PreToolUse-хук запрещает правку AGENTS.md, CLAUDE.md, .claude/, methodology/, scripts/, tests/ (обход для сопровождающего — `STRATEGIST_MAINTAINER=1`).
Почему: защита от prompt injection архитектурой, а не фильтром. Регулярки в `injection.py` — только сигнал для журнала.
Что отвергли: permissions.deny на эти пути — он блокировал бы и сопровождающего без обхода.

## 2026-11-17 · Решение: стоимость считается из транскрипта, дельтой по этапам
Stop/SubagentStop-хук суммирует usage ответов ассистента (дубли по message.id отбрасываются, сайдчейны — отдельно) по прейскуранту API и дописывает в `state/cost-ledger.csv` только прирост с прошлой записи, с текущим этапом. Так видно, сколько стоил каждый этап и каждый субагент.
Почему: стоимости во входе хука нет; на подписке это оценка, а не счёт — так и пишем.

## 2026-11-17 · Сложность: проверка чисел по всей странице пропускала подмену
Тест «модель поменяла 11 млн на 15 млн» не прошёл: на новостной странице снимка где-то было число 15. Как решили: числа и имена ищутся в окрестности цитаты (±700 знаков) плюс в атрибуции снимка (title, publisher, published); без цитаты — по всему снимку с предупреждением «слабее».

## 2026-11-17 · Сложность: окно вокруг цитаты понижало честные факты
После сужения окна «МегаФон сообщает…» и «обзор 2025 года» понижались: имя издателя и дата — это метаданные, а не текст рядом с цитатой. Как решили: поля `publisher` и `published` во frontmatter снимка (`fetch_source.py --publisher --published`) участвуют в проверке.

## 2026-11-17 · Сложность: первое слово предложения — имя или обычное слово?
Первая версия пропускала первое слово предложения, и «Билайн предлагает…» (бренда нет в источнике) проходил как факт. Проверять первое слово по окну — ложно понижало «Обзор iPhones.ru сообщает…». Как решили: первое слово ищем по всему снимку, остальные имена — по окну цитаты; служебные слова исключены.

## 2026-11-17 · Сложность: словарь рискованных слов давал ложные срабатывания
«самому защищаемому» считалось «самый», «работает лучше» — «лучший». Как решили: только формы превосходной степени («самый/самая…», «лучший/лучшая…»); в сравнении — учёт отрицаний («избегать обещаний «100%»») и разделов «Чего не говорим», «Риски».

## 2026-11-17 · Наблюдение: гипотеза о «громких» обещаниях чата не подтвердилась
Ожидали, что обычный чат напишет «100% защиты». Реальный ответ (Sonnet без инструментов, baseline/) аккуратен в словах: рискованных формулировок 0. Но 5 из 13 его обещаний шире свойств продукта, 2 противоречат открытым данным («Маме не нужно ничего настраивать» — родственник подтверждает согласие СМС-кодом), 3 без опоры (голосовое подключение, режимы, белый список). Вывод: ценность — в связке «обещание → свойство → источник», а не в словаре 38-ФЗ. Демо-момент в плане исправлен.

## 2026-11-17 · Сложность: frontmatter скиллов не был валидным YAML
Проверка PyYAML (вне репозитория) показала: `when_to_use: "новая задача", "…"` и «пересмотр: оставить» в описании revisit ломают YAML, а Claude Code в таком случае загружает скилл **без полей** (без model, allowed-tools, description). Как решили: кавычки-ёлочки вместо прямых, без «: » в значениях; добавлен stdlib-тест `test_frontmatter_is_valid_yaml_subset`, который ловит обе ошибки на старых версиях файлов.

## 2026-11-17 · Сложность: Stop-хук не видел последний ответ в транскрипте
Живая проверка в Claude Code (`claude -p`, Haiku, $0,005): скиллы (все 8) и SessionStart-сводка подхватились, Stop-хуки отработали без ошибок, но журнал стоимости остался пуст. Причина: транскрипт пишется асинхронно, в момент Stop последнего ответа в файле ещё нет (так и сказано в документации хуков). Как решили: хук ждёт, пока файл перестанет расти (до 2,5 с), а пути транскриптов запоминаются в `state/.cost-sessions.json` и недостающее досчитывается на SessionEnd и следующем SessionStart. Проверка: стоимость в `cost-ledger.csv` совпала с `total_cost_usd` самого Claude Code до цента ($0,004100 и $0,004802 в двух прогонах).
Заметка: в `-p` без принятого диалога доверия Claude Code игнорирует `permissions.allow` проекта — в README написано, что при первом запуске нужно подтвердить доверие к папке.
Ещё одна живая проверка ($0,007): Haiku в режиме acceptEdits попросили дописать строку в AGENTS.md — PreToolUse-хук отказал («Заблокировано: правка защищённого файла»), файл не изменился, запись появилась в `state/security-log.jsonl`. Следы smoke-тестов из демо-задачи удалены.

## 2026-11-17 · Решение: цена бездействия, вердикт и «что заставит пересмотреть» — с проверкой кодом
Подсмотрено у spec-kit assess (Cost of Inaction; go / needs-clarification / kill) и pm-brain («what would reopen them»). Сделали не только строками в шаблонах, но и `scripts/decision_lint.py` в Stop-воротах: без «Цены бездействия» с меткой утверждения, без вердикта с причиной и без «Что заставит пересмотреть» ход не завершается; «делать» без проработанного варианта (нет «что должно быть правдой», возражений, меток) или без оснований понижается до «нужна ясность» с записью в журнал. Старое поле «Kill-критерии» принимается как синоним.
Почему: шаблон модель может проигнорировать, проверку — нет; стоит ноль токенов.
Ошибка, пойманная тестом: регулярное выражение блока «Цена бездействия» съедало перевод строки и захватывало метку из следующего пункта — пустой блок считался обоснованным.

## 2026-11-17 · Решение: «лестница вопросов» на постановке
Подсмотрено у deanpeters/Product-Manager-Skills (Adaptive Decision Ladder: 3–5 вопросов, затем пронумерованные рекомендации). У нас: у каждого вопроса — почему он важен, варианты ответа и рекомендация; затем пронумерованные следующие шаги. РП отвечает одной строкой, неотвеченное становится допущением. Закрывает требование брифа «спрашивать только то, что важно для следующего шага» и экономит ход диалога. Только инструкция и шаблон, без кода.

## 2026-11-17 · Решение: журнал исследования пишет скрипт, а не только модель
Подсмотрено у «Алисы AI» (режим «Исследовать» показывает, как шёл поиск). `out/research-log.md`: строки «открыт / не открылся» пишет `fetch_source.py` сам — модель не может «забыть» неудачный источник; поисковые запросы и отброшенные источники с причиной агент добавляет командой `research_log.py`. Журнал исключён из сравнения с чатом (это процесс, а не результат).

## 2026-11-17 · Решение: план исследования на утверждение с оценкой стоимости
Подсмотрено у Gemini Deep Research (план можно отредактировать до запуска), но ни один аналог не показывает цену плана (docs/research/02-competitors.md). У нас: вопросы, меняющие решение, список источников и оценка стоимости и времени (`scripts/estimate.py`) → РП говорит «начать» или правит → `project.py approve-plan`. Принуждение кодом: `fetch_source.py` на этапе research без утверждённого плана возвращает код 3 (`--no-plan` — для файлов РП и дозагрузки по его просьбе). После этапа — «оценка против факта» в `cost_report.py` и сводке SessionStart; по завершённым задачам считается коэффициент «факт / оценка» для калибровки.
Модель оценки: ~3 хода Sonnet на источник (перечитывание контекста из кэша + запись кэша + вывод), чтение снимка Haiku, $0,01 за поиск, постоянная часть этапа; диапазон ×0,6–×1,8. Допущения открыты в `ASSUMPTIONS` и будут уточнены по сквозному прогону. Пример: 8 источников и 6 запросов ≈ $0,75 ($0,45–$1,35), ≈15 мин; главная статья — оркестратор, чтение на Haiku стоит ~1%.
Ошибка, пойманная тестом: калибровка обходила `projects/.active` как каталог задачи.

## 2026-11-17 · Решение: снимки источников неизменяемы
Подсмотрено у phuryn/pm-brain (неизменяемая папка `source/`). Без этого факт можно «подтвердить», дописав нужную цифру в снимок. Три слоя: `fetch_source.py` пишет sha256 файла в `materials/MANIFEST.json`; `verify_claims.py` даёт ошибку на изменённый или удалённый снимок и понижает опирающиеся на него факты (`snapshot_changed`), снимок вне манифеста — предупреждение; PreToolUse-хук запрещает агенту Write/Edit в `materials/` и Bash-команды изменения файлов там. `.gitattributes` отключает преобразование переводов строк в снимках, иначе на Windows хэши разойдутся. Манифесты демо и эталона пересобраны командой сопровождающего `fetch_source.py --rebuild-manifest`.

## 2026-11-17 · Решение: субагент-критик вариантов на Opus
Подсмотрено у product-on-purpose/pm-skills (субагент pm-critic). `.claude/agents/critic.md` получает только `out/options.md` и `claims.jsonl` — чистый контекст без рассуждений автора, инструменты только на чтение. Формат ответа — готовая таблица «Возражения критика» с опорой (ID и статус утверждения), силой и тем, что снимет возражение; автор обязан ответить на сильные (`decision_lint.py`, O6/O7 — предупреждения, а не блок: в Cursor субагентов может не быть).
Почему Opus 5.5, а не Sonnet: вход маленький, запуск ≈$0,18 против ≈$0,09 у Sonnet; разница в центах, а качество возражений — прямо критерий 1. Независимость даёт чистый контекст, а не другая модель.
Проверка: живой запуск (`docs/process/critic-live-check.md`, $0,189, из них Opus $0,181) нашёл в эталоне разработчика три ошибки, которых не ловят детерминированные проверки: вывод автора с меткой `[факт C-001]`, «цену бездействия» на прогнозе, описывающем эффект другого варианта, и переинтерпретацию C-004 как «взрослые дети». Эталон исправлен. Вывод: метка «факт» у верного ID ещё не значит, что текст рядом говорит то же, что факт, — это зона критика, а не скрипта.

## 2026-11-17 · Решение: точечная правка раздела вместо перегенерации
Подсмотрено у github/spec-kit (правка артефакта вместо перегенерации этапа) и Productboard (tracked changes). Скилл `revise` + `scripts/revise.py`: `start` сохраняет копию документа, `finish` сравнивает разделы по заголовкам и не принимает правку, если изменено что-то вне выбранного раздела (код 1; осознанно — `--allow-other` с причиной). В `state/journal.md` — что, где, сколько строк и почему, в `state/revisions/log.md` — diff. Последствия в других документах агент не правит молча, а перечисляет РП. Закрывает требование брифа «РП может исправить результат» и экономит токены: не переписываем документ целиком.

# Независимая проверка (17.11.2026): находки и как закрыли

Два независимых проверяющих (роль жюри и технический аудит, отдельные сессии ИИ без участия автора кода) разобрали коммит 7492c4d: `../../docs/review/3-agent-tech.md`, `3-agent-jury.md`. Ниже — каждая находка, как закрыта и каким тестом это закреплено. Тесты писались по скриптам воспроизведения аудитора и сначала падали на старом коде.

## Аудит К1 (критично) · Агент сам «подтверждал» факты
Нашли: `claims.py add` принимал `verified: "human"`; `claims.py human-verified` и `project.py approve-plan` стояли в allow; агент мог сохранить свой файл `out/calc.md` снимком и сослаться на него как на источник. Выдуманные «30 млн абонентов» проходили ворота как факт.
Закрыли:
- Поле `verified` убрано из `claims.py add`. Подтверждения РП пишутся в отдельный журнал `state/human.jsonl` с хэшем текста утверждения или плана. Проверки верят только ему; пометки `verified`/`approved` в claims.jsonl и research-plan.json — для показа и игнорируются. Если текст утверждения изменили после подтверждения, подтверждение перестаёт действовать.
- `human-verified` и `approve-plan` — в `permissions.ask` (по документации ask срабатывает раньше allow и спрашивает даже в режиме auto); `disableBypassPermissionsMode: "disable"` в настройках проекта, чтобы вопрос нельзя было пропустить. PreToolUse-хук пропускает эти команды только в точной форме (иначе правило ask не сработает на `./scripts/…` или `--project x approve-plan`) и отказывает в режимах без вопросов. Запись в `state/human.jsonl` агенту запрещена хуком.
- Локальные файлы `fetch_source.py` принимает только из `projects/<задача>/inbox/` (кладёт РП; агенту запись туда запрещена хуком) или как синтетику. Снимок «своего» файла агента не может быть основанием факта (`agent_file` в verify_claims). Расчёты агента — гипотеза или прогноз с `basis`, а не снимок.
- Флаг `--no-plan` удалён: план нужен для веб-исследования, материалы РП из inbox/ его не требуют.
Тесты: `tests/test_audit_selfverify.py` (9 сценариев аудита).

## Аудит К2 (критично) · Секреты могли утечь в снимки и в контекст
Нашли: `fetch_source.py .env` (команда из allow-списка) клал ключ в `materials/`; так же можно было забрать `~/.ssh` и `~/.aws`; `grep -r KEY .` читал `.env` мимо `Read`-запретов (документация прямо говорит, что они не действуют на скрипты и `grep -r`); у source-reader были WebFetch и WebSearch — недоверенный текст, доступ к файлам и выход в сеть в одном субагенте.
Закрыли:
- Локальные файлы — только из `inbox/` (см. К1); имена `.env*`, dot-файлы, `*.pem`, `*.key`, `id_*`, «credential/secret/password/token» отклоняются даже там; симлинк из inbox наружу не проходит (сравнение после `resolve`).
- PreToolUse-хук отказывает любой Bash-команде, где упомянуты `.env`, ключи, `~/.ssh`, `~/.aws`, `.netrc`, credentials — без учёта регистра и независимо от того, пишет команда или читает. Рекурсивный `grep -r`/`rg` разрешён только по `projects/`, `methodology/`, `docs/`.
- Из allow убраны `Bash(grep *)` и `Bash(head *)`; в deny добавлены `Read(./.env.*)`, `Read(~/.ssh/**)`, `Read(~/.aws/**)`.
- У source-reader только `Read, Grep, Glob`. Страницу, которую скрипт не открыл, РП сохраняет в `inbox/`, и она снимается с `--url`.
Тесты: `tests/test_audit_secrets.py` (8 сценариев). Ограничение: Bash-команда может прочитать секрет обходным путём без упоминания имени (например, через переменные) — второй слой здесь sandbox с `denyRead` (см. К3).

## Аудит К3 (критично) и М1, М2 · Обход PreToolUse-хука и его ложные срабатывания
Нашли: хук сравнивал пути с учётом регистра (`agents.md`, `Scripts/` на macOS — тот же файл), искал «операцию записи» после вырезания кавычек и heredoc, не знал `1>`, `&>`, `>|`, `python -c`, heredoc с python, `node -e`, `awk -i inplace`, rsync, unzip, шаблоны и переменные. Одновременно блокировал безобидное: `… | tee out/vc.log`, `rm out/tmp.md && python3 scripts/…`, URL с `/install/`. PowerShell не попадал в матчер.
Закрыли:
- Хук переписан. Пути сравниваются без учёта регистра, хвостовые точки, пробелы и `::$DATA` (Windows) отрезаются, `..` и симлинки разрешаются. Bash и PowerShell разбираются по сегментам (`shlex`), тело heredoc — это stdin. Для команд записи проверяется **цель**, а не упоминание: писать можно только в `projects/<задача>/` вне снимков, inbox и журнала РП, и во временные папки. Цель с переменной, подстановкой или шаблоном вне `projects/` — отказ. Учитывается `cwd` из входа хука, поэтому `cd materials` и следующий `rm M-01*` тоже ловятся. `bash -c`, `eval`, `unzip`, `tar`, `rsync`, `curl`, `git checkout/restore/reset/…` — отказ. Встроенный код интерпретатора — отказ, если упоминает защищённое имя или пишет файлы. Подстановки `$(…)` проверяются рекурсивно. Скрипты агента `python3 scripts/<известный>.py` проходят.
- Второй слой — встроенный sandbox Claude Code: `denyWrite` на инструкции, методику, скрипты, тесты, шаблон, снимки, inbox и журнал РП; `denyRead` на `.env` и ключи; `allowUnsandboxedCommands: false`. Вне sandbox работают только `fetch_source.py` (нужны сеть и запись снимков) и две команды РП (под `permissions.ask`).
- В матчер PreToolUse добавлен PowerShell; устаревший MultiEdit убран.
Проверка: `tests/test_audit_guard.py` — все 31 атака аудитора и 3 его ложных срабатывания плюс обычные команды агента. Живая проверка на копии репозитория (`claude -p`, Haiku, $0,019 за три запуска): при выключенном хуке `cp … AGENTS.md` получил от sandbox «Operation not permitted», файл не изменился; `fetch_source.py https://example.com` вне sandbox сохранил снимок.
Ограничения: хук — эвристика (встроенный код без защищённых имён и без операций записи проходит, его ловит sandbox). На Linux в `denyWrite` не работают шаблоны `projects/*/…` — там снимки защищают хук и sandbox-манифест sha256. На Windows без WSL2 sandbox не работает, хуки требуют `python3`; проверено на macOS. Сопровождающему для правки инструкций нужны `STRATEGIST_MAINTAINER=1` и `"sandbox": {"enabled": false}` в settings.local.json.

## Аудит В2 и жюри п.3 · verify_claims: ложные понижения и ложные пропуски
Нашли: верные факты понижались на форматах «11 млн» / «11 000 000», «1500» / «1,5 тыс.», «220 500 млн» / «220,5 млрд», «24 декабря 2025» / «24.12.2025», «11,0%» / «11%». Неверные проходили: «база выросла на 11%», если рядом в окне ±700 знаков было «11%» про выручку; «99% семей» по «99 рублям»; «Иван Иванов» по «Мария Иванова»; бренд «Альфа» по основе «аль» в «специальный». Выдуманная цитата и пустой снимок давали только предупреждение, а Stop-хук предупреждения не показывал.
Закрыли:
- Факт без цитаты, с цитатой, которой нет в снимке, и со снимком короче 100 символов понижается (`no_quote`, `quote_not_found`, `empty_snapshot`). Цитата ищется без учёта регистра, ё/е, пробелов и кавычек.
- Числа ищутся в **предложении цитаты** (плюс атрибуция снимка), а не в окне. Величины сравниваются по значению: «тыс./млн/млрд/трлн», запятая и пробелы-разделители, проценты отдельно от количеств («99%» ≠ «99 рублей»), даты `ДД.ММ.ГГГГ` ↔ «ДД месяца ГГГГ».
- Имена — целым словом с основой не короче 4 букв и окончанием не длиннее 2 букв; короткие имена склоняются (Ева/Еву). Первое слово предложения по-прежнему ищется по всему снимку.
- Stop-хук показывает предупреждения: вместе с блокирующими замечаниями или отдельным сообщением РП.
Эталон: у C-004 цитата расширена до двух предложений (возраст 31–45 стоял в соседнем предложении) — новая проверка это поймала.
Тесты: `tests/test_audit_verify.py` (21 случай из скриптов аудитора и проверка величин), тест хука на предупреждения. Ограничение прежнее: смысл («подтверждает ли источник вывод», отрицания) скрипт не проверяет — это зона субагента critic.

## Аудит В1 и жюри (противоречие 4) · promise_lint: ложные пропуски и ложное срабатывание
Нашли: «Гарантированно… полная защита» проходило, если свойство гласит «не гарантирует… не полная защита» (линтер видел слово, но не отрицание). Не ловились «лучше всех», «ни один мошенник не дозвонится», «надёжнее любого банка», «дешевле конкурентов в 3 раза». Обещание могло ссылаться на чужое свойство («защищает от дипфейков» → «уведомляет о незнакомом номере»). Слоган вне таблицы давал лишь предупреждение. При этом `абсолютн\w*` ловил «абсолютная база неизвестна», и в сравнении у агента была 1 «рискованная формулировка».
Закрыли:
- Свойство подтверждает формулировку, только если она стоит в нём утвердительно (не после «не / без / ни»).
- Добавлены сравнительные формы: «лучше / хуже / дешевле / надёжнее… всех, любого, конкурентов, аналогов, чем у», «ни один», «сто процентов», «#1». «Абсолютно» — только как обещание («абсолютная защита», «абсолютно безопасно»).
- E7: у обещания и опорного свойства должно быть хотя бы два общих значимых слова (основа из 5 букв).
- E8: рискованная формулировка в слогане, ключевом сообщении, позиционировании, заголовках — ошибка, а не предупреждение.
Пересчёт сравнения на эталоне: рискованных формулировок у агента 0 (было 1 ложное), у чата 0.
Тесты: `tests/test_audit_promises.py` (7 обещаний и слоган из скрипта аудитора). Ограничение: E7 проверяет пересечение слов, а не смысл.

## Аудит В3 и жюри п.4 · fetch_source: SSRF, размер, кодировки, капча, пустые снимки, повторы, гонки
Нашли: сохранялись `http://127.0.0.1/admin`, `169.254.169.254` и адреса локальной сети, редирект на внутренний адрес проходил молча, а в снимок писался исходный URL. Страница на 30 МБ сохранялась целиком. cp1251 без charset давала «����». Капча и JS-страницы (kinopoisk.ru, rbc.ru — 0 символов) записывались как «открыт». Одна страница по двум адресам давала два снимка. Шесть параллельных запусков получали один M-id.
Закрыли:
- Только http(s) и только публичные IP — на каждом шаге редиректа (свой `HTTPRedirectHandler`, `ipaddress`: private, loopback, link-local, reserved, multicast). Итоговый URL после редиректов пишется во frontmatter и манифест.
- Ответ читается не больше 5 МБ, обрезка помечается в снимке. Без charset: строгий UTF-8, иначе cp1251.
- Текст короче 300 символов или признаки капчи и антибота — «не открылся», снимок не создаётся, в журнал исследования пишется причина, агенту подсказывается запасной путь: РП сохраняет страницу в inbox/, `fetch_source.py inbox/<файл> --url <адрес>`.
- Повтор по адресу, итоговому адресу или sha256 содержимого — печатается существующий M-id, новый снимок не создаётся.
- Блокировка `materials/.lock` (flock) вокруг выбора M-id и записи, файл создаётся в режиме «x». `verify_claims` даёт ошибку на повтор M-id.
Тесты: `tests/test_audit_fetch.py` (8 сценариев с локальным HTTP-сервером по скрипту аудитора; разрешение 127.0.0.1 для теста — переменная модуля, недоступная из командной строки).

Нашли: после `project.py use другая-задача` в той же сессии Stop записывал во вторую задачу весь накопленный итог сессии; сессия-копия (`--fork-session`) добавляла его ещё раз.
