# Ключевые постановки задач и результат

Журнал для раздела «ключевые промпты и инструкции» в описании работы (бриф §7.4). Только постановки, повлиявшие на продукт. Инструкции самого агента — в `AGENTS.md`, `.claude/skills/*/SKILL.md`, `.claude/agents/source-reader.md`.

## 2026-11-11 · Ресёрч и идеи (плагин hackathon: kickoff)
- **Постановка:** четыре параллельных ресёрчера (прошлые победители, конкуренты, предметная область, технологии) → три генератора идей с разных углов (боль, ниша, вау-демо) → независимый судья по критериям §8.
- **Результат:** `docs/research/01–04`, `docs/ideas/*`, выбор состава в `docs/ideas/critique.md` §5: ядро из 5 скиллов и «ворота качества» (Сверка обещаний и Протокол доказательств-lite) вместо графа зависимостей и eval.

## 2026-11-17 · Сборка репозитория агента (ведущий разработчик — Claude Code, Opus 5.5)
- **Постановка (сжато):** «Ты ведущий разработчик репозитория ИИ-агента. Прочитай бриф §4–§8, критику идей §0/§4/§5, ресёрч технологий и предметной области. Выбранное не пересматривай: 5 скиллов, раздельное хранение, SessionStart-сводка, журнал стоимости, маршрутизация Haiku/Sonnet/Opus, source-reader без Write/Bash, PreToolUse-запрет правки инструкций, ворота качества на чистом Python (promise_lint, verify_claims, compare) с юнит-тестами. Демо — на открытых данных, без сквозного прогона через `claude -p`. Перед использованием фич Claude Code сверяйся с актуальной документацией. Маленькие коммиты по-русски, без соавторства Claude».
- **Как проверялось:** формат хуков, frontmatter скиллов и субагентов, settings.json сверены с code.claude.com/docs (hooks, skills, sub-agents, settings); формат транскрипта (usage, дубли message.id) — по реальному локальному транскрипту; цены — по справочнику Claude API (кэш 03.11.2026).
- **Результат:** структура «агент / материалы разработки», 8 скиллов, субагент, хуки на 5 событиях, 9 скриптов, 75 тестов. Ошибки, пойманные тестами, записаны в `docs/decisions.md`.

## 2026-11-17 · Ответ «обычного чата» для сравнения
- **Постановка:** один вызов Sonnet 5.5 без инструментов и без материалов задачи, роль «обычный чат-ассистент», тот же запрос руководителя продукта:
  > Я руководитель продукта «Защита близких» в голосовом ассистенте Ева (МегаФон): абонент добавляет номера родственников, и Ева блокирует или разрывает звонки мошенников на эти номера и присылает абоненту уведомление. Хочу увеличить число подключений. Кому и как продавать эту опцию и что сказать аудитории, чтобы она поняла ценность? Подготовь продуктовую и коммуникационную стратегию (с ключевыми сообщениями) и план проверки.
- **Результат:** `projects/demo-zashchita-blizkih/baseline/chat-answer.md` (без правок), `meta.json`. Наблюдение: рискованных формулировок нет, но из 13 обещаний 2 противоречат открытым данным и 3 без опоры (см. `docs/decisions.md`).
